# 方案：消除匿名访客与爬虫的 auth 接口调用（简化版）

- 日期：2026-11-23
- 状态：待评审
- 前提：**不需要覆盖 `*.pages.dev` 直连**（用户已确认）

---

## 一、结论

用 **localStorage 本地标记**判断"这台浏览器登录过没有"，没有标记就不发请求。

改动 **3 个文件、约 20 行**。零后端改动、零 Worker 改动、零新 cookie。

---

## 二、问题回顾

24 小时内 `/api/auth/me` + `/api/admin/auth/me` 共 **1,436 次调用**，占全部 API 流量 96%，其中 153 次返回 504。

其中 80% 来自 Bytespider（新加坡渲染节点），它每渲染一页就发 2 次，拿到的全是 `{user:null}` / `{admin:null}`。

---

## 三、为什么不用前几版方案

**HTML 注入（meta）**：`site` 主站页面走 `context.next()` 直接返回静态文件，不经过任何 HTML 处理。要注入得先给主站加 HTML 读取改造（把流式响应改成全量拼接），再改子站三处注入点 —— 4 处改动，还带性能代价。**更复杂，否决。**

**服务端写标记 cookie**：要动 portal 的 login/register/logout + admin 的 login/logout 共 5 个接口，还要保证 `Max-Age` 与 session cookie 严格同步，且必须把 `'Set-Cookie': cookie` 的单值写法改成 `headers.append`（改错就会丢掉 session，用户直接登不上）。**风险与改动面都不小，否决。**

**合并两个接口**：只能 2 次降 1 次，匿名请求照样存在。**收益不足，否决。**

---

## 四、采用方案：localStorage 标记

### 逻辑

登录成功 → 前端写一个 localStorage 标记；之后每次页面加载先看标记，**没有就说明这台浏览器没登录过，直接跳过网络请求**。

爬虫不携带 localStorage，所以全部跳过。匿名真人也没登录过，同样全部跳过。

只有真正登录过的浏览器，才会继续调接口核实（防止 session 已过期）。

### 为什么可靠

httpOnly cookie 是给服务端看的，前端读不到；但前端不需要知道"session 是否有效"，只需要知道"要不要去问"。

localStorage 刚好承担这个：它是前端自己的记忆，与服务端 session 状态无关，但能过滤掉「从来没有登录过」这一大类请求 —— 而那正是 96% 流量的来源。

### 改动清单

| 文件 | 改动 |
|---|---|
| `packages/ui/src/AuthProvider.tsx` | 调用前读标记；登录成功写标记；登出成功删标记；接口返回 null 时自动删标记 |
| `packages/ui/src/LanguageSwitcher.tsx` | 调用前读 admin 标记，无标记直接返回 false |
| `apps/admin/src/lib/auth.ts` | admin 登录成功写 admin 标记；登出删标记 |

实现要点：

1. 读 localStorage 必须包 `try/catch` —— 隐私模式下会抛异常，异常时按"无标记"处理（不发请求），功能不坏。
2. 接口返回 `null` 时要顺手删标记 —— 这样 session 过期后能自动纠正，不会一直白调接口。
3. 标记里不存任何身份信息，只存 `1`。防伪造不靠它，安全校验全在服务端。

### 收益

| | 现在 | 之后 |
|---|---|---|
| 每日 auth 调用 | 1,436 | 约 50–100 |
| 每日 504（auth） | 153 | 接近 0 |
| 爬虫每页请求 | 2 | 0 |
| 匿名访客首屏 | +2 请求 | 0 |

## 五、代价（要认的三条）

**1. 已登录用户换设备或清缓存后，页脚会显示"登录"**

点击后进 `/c/login/`，服务端检测到 session 会直接跳到账户页。多点一次，不会进错地方。

**2. 非交互式登录（如邮件链接）后，前端不知道**

同上，第一次会显示"登录"，进去后自动到账户页，此时可以补写标记（可选优化）。

**3. `tc-web-admin.pages.dev` 直连时标记不共享**

不同 origin，localStorage 隔离。用户已确认不管 DEV 直连，接受。

这三条都不破坏功能，只影响"入口文案"。
