保税项目能不能做，先花两到四周做一次诊断，四份报告到手再决定是否继续。决定继续，就用一个 SKU 走六到十周试点，首单跑通才放量。每一步都能停，停的时候已经交付的东西归品牌方。三句话就是整条入场路线，剩下的问题只有一个：把它拆成谁签字、谁交付、什么时候验收。

十四个工作包，S0 到 S13，从诊断、主体、店铺、备案、头程、清关，一直排到结算、推广、售后、数据、审计、供应链可视、内容合规与会员。三步进场是商务节奏，不是分期交付：诊断覆盖 S0，试点覆盖 S1 到 S5，放量覆盖 S6 到 S13。包是交付单位，步是决策节点，两者不要混。

## 三步入场与十四个工作包，先看全图

图上三级台阶，三个数字先记住：3 步入场、3 个退出点、4 份 S0 交付件。

第一级诊断，覆盖 S0，两到四周，产出四份报告；第二级单 SKU 试点，覆盖 S1 到 S5，六到十周，链路五步逐段落地；第三级放量，覆盖 S6 到 S13，全 SKU，八个模块逐个启用。每级台阶右端有一个空心断点，意思是走到这一步结束就可以退出，已经交付的文件归品牌方。

## 第一步诊断，两到四周买一个明确的答复

诊断这一级只做一件事：把能不能进、怎么进判定清楚。产出四份报告，一次交齐：

- 准入专项报告：回答能否准入，给出税号、清单与监管条件；
- 合规依据报告：回答有没有阻断性问题，每一条结论带文号；
- 执行推进清单：回答何时准入，列出先后顺序与所需材料；
- 口岸执行口径核验清单：回答口岸怎么执行，同一税号在目标口岸的实际口径。

诊断是固定价服务，费用以书面报价为准，检测与差旅据实另计。报告到手，决定继续或停止；已付费用对应已交付件，不需要为没有发生的阶段买单。

诊断的价值常常是买一个不字。有一个固体饮料品牌，配方里两种成分让归类与正面清单资格都悬着。诊断报告把税号、清单与口岸口径列清楚，品牌改配方之后再进试点。诊断费只是零头，真正省下的是后面整条链路的返工。

四份报告也不是四份演示文稿。准入专项报告要能指到具体税号，合规依据报告要能指到具体文号，执行推进清单要能排到具体材料，口岸口径核验清单要能对上具体口岸。任何一份停留在原则层面，试点就会把问题重新演一遍。

## 第二步单 SKU 试点，六到十周跑通一票

试点只做一个 SKU，链路五步，顺序不能换：

- 主体设立：营业执照与海关登记，缺一样系统开不了户；
- 平台店铺：店铺上线、收款账户与支付通道；
- 商品备案：分级表、归类与单证，税号定错，后面每次申报都要改；
- 保税仓头程：货进保税仓，保税账册开起来，库存对品牌方可见；
- 三单清关：订单、支付、物流三单对上，首票放行。

链路跑通并确认之后，才谈结算与分润。

试点期有四个观察项，决定能不能放量：首单是否跑通、成本偏差有多大、复购信号是否出现、有没有合规问题。四项里有一项不达标，就回退。回退不等于失败，是把放量的钱留在口袋里；已交付件仍然归品牌方。

一个 1800 盒的维生素 C 泡腾片批次，首单 240 盒完成清关出区。第二周复盘，单均履约成本比报价高 22%，差在拣货按整箱拆零。团队把包装改成六盒一箱，成本回到约定区间，才进入放量。这一轮没有加预算，加的是两周时间和一次包装调整。

如果首单没跑通，先查三单是否一致、备案是否覆盖该 SKU、成本口径是否含拆零与退货。查清再决定回退还是重跑，不要带着问题放量。

## 第三步放量，八个模块按依赖顺序开

放量覆盖 S6 到 S13，八个模块逐个启用，次序就是依赖顺序：

- 资金结算：对账单与单证，试点跑通后先开；
- 推广分销：获客与增长架构，先有稳定履约再放量投放；
- 客服售后：售后与退货处理，退货流程没建好，会员数据就是脏的；
- 数据风控：数据合规与出境，先划清哪些数据能出境；
- 合规审计：自查、留痕与问询应答，平时留痕，问询时才答得出；
- 供应链可视化：订单、库存、清关、物流放在同一视图里；
- 内容合规：详情页与直播审查，素材上线前过一遍；
- 会员运营：分层与周期购，等复购稳定后再做等级。

放量不是把所有 SKU 一次铺开。按合同约定的阶段开，每一阶段有验收件，未达标就停在这一级。停下来的成本，通常比带着问题铺开的成本低。

启用节奏与首期范围在六阶段路线图里定；逐模块的交付件与做法在服务清单总表里，不在这张图上。

## 十四个包按签字权切，每一分包对应一个交付件

十四个工作包不按系统切，按签字权切。每一个包对应一个能单独验收、单独追责的交付物：诊断报告有人签，执照有人签，备案回执有人签，结算单也有人签。签字的人就是这个包的责任人。

| 编号 | 工作包 | 交付件 |
|---|---|---|
| S0 | 诊断与准入 | 四份报告一次交齐 |
| S1 | 主体设立 | 营业执照与海关登记 |
| S2 | 平台店铺 | 店铺上线、账户与支付 |
| S3 | 商品备案 | 分级表、归类与单证 |
| S4 | 保税仓头程 | 保税账册与库存可视 |
| S5 | 三单清关 | 订单、支付、物流三单与首票放行 |
| S6 | 资金结算 | 对账单与单证 |
| S7 | 推广分销 | 获客与增长架构 |
| S8 | 客服售后 | 售后与退货处理 |
| S9 | 数据风控 | 数据合规与出境 |
| S10 | 合规审计 | 自查、留痕与问询应答 |
| S11 | 供应链可视化 | 订单、库存、清关、物流 |
| S12 | 内容合规 | 详情页与直播审查 |
| S13 | 会员运营 | 分层与周期购 |

这样切，报价与验收都落在包上。你付费的对象是十四个交付物；哪一格没交付，对应的包就不验收。故障定位也有坐标：先说是哪一格，再谈是谁的人。

包与包有先后。S0 不定案，S1 与 S3 不能开工；S3 的税号不定，S4 的入仓预报就是错的；S5 跑顺一票，S6 才谈得上对账。顺序错了，返工的成本比省下的时间贵。

方案阶段还要留两个接口位：9610 直购通道与第二货源。某个品类只能走直购，或者保税仓临时没有库容，订单从 9610 出，账仍记在同一套台账；同一个 SKU 认证两个境外发货主体，一个的资质或物流出问题，另一个顶上。接入位首期建好，将来不用改架构。

## 每一步怎么退，退出条款写清三件事

退出点不是一句礼貌用语，是合同条款。写清楚三件事：

- 退出的时点：每步结束、报告或交付件验收之后，不是中途拍脑袋；
- 已交付件的归属：报告、账号、数据、备案回执与账册归品牌方；
- 未发生费用的处理：按书面报价与实际发生结算，S0 固定价，检测与差旅据实。

三步入场是商务节奏，不是分期交付。如果产品与路径已经清楚，可以只做单 SKU 试点；产品越新、成分越复杂，越不建议跳过诊断。

放量阶段的退出按合同约定的阶段执行。未达标就停在这一级，交接按六项清单走。费用以书面报价为准，条款以正式合同为准。

## 这套走法不覆盖什么

框架管结构，不管选择。四件事它不回答：

- 产品走哪条注册路径，蓝帽子、保税、一般贸易怎么取舍，要看品类、成分与预算；
- 定价与渠道，平台怎么选、价格带怎么定、大促怎么排；
- 境内主体的股权与税务架构；
- 具体品类的准入判定，每个税号都要单独核对清单与监管条件。

这套走法管的是项目怎么拆、怎么验收、什么时候停。它不替代准入判定，也不替代税务与法律意见。

## 为什么现在动，晚一步让出的是什么

合规先入场的品牌，会锁定三样后来者更难拿的东西：综合保税区的账册与口岸备案资质位、平台同类目的信任成交位、核心客群对成分的认知。晚一步，同一套门槛还在，排队更长。

该等的时候也要等：品类不在正面清单、买家不是个人自用、单笔金额超过限值，三条有一条不成立，先把准入解决，不要启动试点。三条都成立，拖延的成本通常比诊断费高。

我们处理过的项目里，最常见的浪费是没定义清楚哪一步结束、哪一步验收。合同签得很厚，格子是空的，出了问题还是找不到人。

保税项目的门槛不在政策，政策是公开的，文号都写在报告里。门槛在结构：一条长链路能不能拆成可签字、可验收、可退出的格子。十四个工作包解决谁交付，三步进场解决什么时候决定继续。两件事都写进合同，项目才算真正开始。
